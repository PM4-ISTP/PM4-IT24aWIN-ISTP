# Development seed data

This directory is reserved for ad-hoc development seed exports. The seed format is plain PostgreSQL SQL generated by `pg_dump`, so it works with the existing Docker Compose database and does not add application tooling.

## Tables

The current code uses these content tables:

- `courses`
- `course_topics`
- `labs`
- `course_labs`
- `challenges`
- `challenge_options`

The issue may mention older names. In the current schema, `labs` are the top-level challenge/lab objects, `challenges` are the per-lab tasks, `challenge_options` stores multiple-choice options, and `course_labs` links courses to labs.

Do not include progress or user-assignment data in dev seed exports:

- `challenge_completions`
- `student_flag_submissions`
- `student_option_submissions`
- `course_enrollments`
- `course_instructors`
- `course_challenge_score_overrides`
- `users`
- `user_roles`

## Export

Start the local database first:

```bash
cd infra
docker compose up -d db
```

Export content data from the project root:

```bash
docker compose -f infra/docker-compose.yaml exec -T db pg_dump \
  --data-only \
  --inserts \
  --column-inserts \
  --on-conflict-do-nothing \
  --table=courses \
  --table=course_topics \
  --table=labs \
  --table=course_labs \
  --table=challenges \
  --table=challenge_options \
  -U postgres \
  postgres \
  > infra/seed/testdata.sql
```

If your local `pg_dump` does not support `--on-conflict-do-nothing`, omit that flag and import into an empty database, or post-process generated `INSERT` statements before sharing the file.

If you prefer host-installed Postgres tools, use the same `pg_dump` flags with `-h localhost -p 5432 -U postgres postgres`.

## Import

Import into a running local database from the project root:

```bash
docker compose -f infra/docker-compose.yaml exec -T db psql -U postgres postgres < infra/seed/testdata.sql
```

PowerShell equivalent:

```powershell
Get-Content infra/seed/testdata.sql | docker compose -f infra/docker-compose.yaml exec -T db psql -U postgres postgres
```

## User FK caveat

`labs.creator_id` is a foreign key to `users.id`. This seed deliberately does not export users, because users are managed through Keycloak-backed application provisioning and should not be moved as generic content seed data.

Before importing a seed file, make sure the target instance already has the creator user IDs referenced by `labs.creator_id`, or edit/re-export the seed so all labs point at a valid local instructor user. If the FK is missing, PostgreSQL will reject the affected `labs` rows and dependent `course_labs`/`challenges` rows may also fail.

## Committing sample data

`infra/seed/testdata.sql` may be committed when a small, useful local-development sample exists. Keep it free of real users, enrollments, submissions, secrets, and staging-only data.
